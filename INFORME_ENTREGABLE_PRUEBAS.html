3. Automatización con Pipeline de CI (GitHub Actions)

Se configuró el flujo de trabajo en .github/workflows/ci.yml para ejecutarse automáticamente ante cada push y pull_request sobre las ramas principales:

name: CI Pipeline - Simulador ICFES

on:
  push:
    branches: [ main, master ]
  pull_request:
    branches: [ main, master ]

jobs:
  test:
    name: Build & Test
    runs-on: ubuntu-latest

    strategy:
      matrix:
        node-version: [18.x, 20.x, 22.x]

    steps:
      - name: Checkout del código
        uses: actions/checkout@v4

      - name: Configurar Node.js ${{ matrix.node-version }}
        uses: actions/setup-node@v4
        with:
          node-version: ${{ matrix.node-version }}
          cache: 'npm'

      - name: Instalar dependencias
        run: npm ci || npm install

      - name: Ejecutar pruebas unitarias y de integración con cobertura
        run: npm run test:coverage
        env:
          NODE_ENV: test
          JWT_SECRET: test_jwt_secret_ci_environment_key_32chars

5. Flujo de Trabajo en Git y Pull Request

  1. Creación de rama individual: git checkout -b norman-pruebas
  2. Confirmación de cambios: git commit -m "feat(tests): agregar pruebas unitarias, integracion y pipeline CI"
  3. Publicación en GitHub: git push origin norman-pruebas
  4. Apertura de Pull Request: Hacia la rama main en GitHub, donde el pipeline de GitHub Actions se activa y valida automáticamente la totalidad de pruebas.
  5. Revisión y Aprobación: El equipo revisa el PR y procede a la fusión (merge).
